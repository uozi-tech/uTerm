# SSH 栈重写计划：跟 Apple 的 swift-nio-ssh，去掉 Citadel

状态：进行中（2026-11-24 立项）。代码在 uAppKit 的 `feat/ssh-stack-apple` 分支及其下的各条分工分支，
没有推送，没有动 uAppKit 与 uTerm 的 main。

## 1. 为什么做

| 现状 | 问题 |
|---|---|
| NIOSSH 用的是 Wellz26 的 fork 0.3.6 | 它在 2022-04 从 Apple 的 **0.4.0** 分出去，之后 Apple 的 95 个提交都没有：超长 mpint、认证次数上限、缓冲上限、最大包长、`readVersion` 崩溃等加固全部缺失 |
| 客户端层用 Citadel 0.12.1 | 上游 2026-04 之后没有提交；我们为它的设计绕了很多路（`withPTY` 只能挂着闭包、`onDisconnect` 只存一个回调、exec 取消不了、登录超时写死要打补丁、`SFTPFile` 不是 Sendable） |
| 两者都是「上游基线 + 补丁重放」 | 给一个不动的上游维护补丁流程，没有回报 |

试编译的结论：把 Apple 0.15.2 原样换进来，NIOSSH 自己能编过；Citadel 缺的只有「自定义密钥类型 / 签名 / 密钥交换」的注册接口。
而 uTerm 今天**实际启用**的算法只有 NIOSSH 的默认集（连接时没传 `algorithms:`），唯一用到扩展接口的是 USSHKit 自己的
RSA 用户私钥（`rsa-sha2-512`）。所以「功能不倒退」需要的补丁面很小。

## 2. 目标形态（uAppKit）

```
Sources/NIOSSH            apple/swift-nio-ssh 0.15.2 + 我们的补丁（sync.sh 重放，流程不变）
Tests/NIOSSHTests         上游自己的测试，一起 vendor 进来，升级时当回归网
Sources/USSHCore          我们的客户端层（新写，替掉 Citadel 的位置）
    Connection/ Channels/     连接、认证、主机密钥、跳板机、exec、PTY、TCP 转发
    SFTP/                     SFTP v3 报文与客户端
    Algorithms/               NIOSSH 没带的：RSA、DH group14/16、AES-CTR + HMAC、chacha20-poly1305
Sources/USSHTestServer    进程内 SSH 服务端，只给测试用（app 的沙盒测试宿主起不了 sshd）
Sources/USSHKit           产品层（主机密钥库、策略、密钥导入、转发隧道），改成依赖 USSHCore
Sources/Citadel           删除
```

依赖方向：`USSHKit → USSHCore → NIOSSH`。USSHCore 不带面向用户的文字（错误用类型和 code 表达，文案在 USSHKit / app），
因此没有多语言负担。Swift 6 语言模式，没有默认 MainActor 隔离。

### NIOSSH 上的补丁（都在 Apple 基线上重做）

| 补丁 | 内容 | 能不能提给上游 |
|---|---|---|
| 密钥扩展接口 | 自定义公钥 / 私钥 / 签名类型的协议与注册表；主机密钥解析、签名校验、用户认证都认它 | 可以，Apple 维护者表态过只接受「扩展接口」而不是把 RSA 合进主线（issue #60、PR #158） |
| 密钥交换扩展接口 | 自定义密钥交换算法的协议、注册、配置项 | 同上 |
| closedRemotely 守卫 | 对端先关 channel 后排空缓冲读时不再发 window-adjust（否则 precondition 崩进程） | 可以，Apple 的 main 至今只有 `sentClose` 守卫 |
| closeFuture 永不失败 | 出错拆除时 `closePromise` 改成 succeed；已关闭 channel 上的打开请求直接失败 | 可以 |
| 修改声明 | Apache-2.0 §4(b) | — |

原则：补丁只做「接口」和「修 bug」，算法实现一律放 USSHCore。以后加算法不用再碰 NIOSSH，上游哪天合了扩展接口，补丁就能删。

### USSHCore 的接口取向

- 全部是句柄式、`Sendable`、能取消：`openShell` / `openExec` 返回句柄（输出流、写入、改尺寸、退出状态、关闭），
  任务取消会关通道。保留 `withPTY` / `withExec` / `executeCommandStream` 这几个带作用域的便捷写法，减少 uTerm 的改动量。
- 断开通知可以挂多个观察者（今天 uTerm 自己包了一层来绕 Citadel 的单回调）。
- 握手与认证的时限是配置项；等用户确认主机密钥的那段时间单独计。
- SFTP 直接做成子通道上的 NIO handler，同一通道多请求并发（uTerm 的流水线传输靠这个）。
- TCP 通道把「在 channel 的 EventLoop 上同步安装 async 读端」做成接口的一部分（1.4.2 那次崩溃的根因）。

每条线一个独立的 git worktree 和分支，只动自己的目录，互不引用对方的内部类型，由主会话合并。

- A 线带出来、第二波要处理的事：
  - 密钥交换接口只让算法做数学（公开值、共享密钥），哈希、主机签名校验、密钥派生仍由 NIOSSH 做，主机密钥校验绕不过去。
  - NIOSSH 0.15.2 **没有 `server-sig-algs`**：RSA 用户私钥只能按 `rsa-sha2-512` → `-256` 依次试，每次占服务器一次认证次数。
  - NIOSSH 0.15.2 **没有 strict KEX（Terrapin 的缓解）**：自带的 AES-GCM 不受影响，但 chacha20-poly1305 和 `-etm` 的 MAC 受影响，
    所以这两类在补上 strict KEX 之前不进默认协商（要再加一个补丁）。
  - 密钥算法的注册是进程级的：注册了就对所有连接生效。SHA-1 的 `ssh-rsa` 默认不注册。
  - RSA 主机密钥要原样存下服务器发来的字节（NIOSSH 会把它重新序列化进交换哈希）。
  - 2048 位的 DH 模幂在 EventLoop 上算，一次几十毫秒；要不要挪出去第二波定。
  - 0.15.2 里 closedRemotely 那个崩溃已经走不到了（对端关闭后立刻回 CLOSE），补丁 0001 留作保险。

  旧的 `hmac-sha1`；RSA 内核（`ssh-rsa` 公钥，`rsa-sha2-512/256` 与旧的 `ssh-rsa` 签名，底层是 swift-crypto 的 BoringSSL）；
  DH 内核（group14-sha256、group16-sha512，旧的 group14-sha1）。主会话复跑 43 个测试全过，其中 18 组加密方式逐一和本机真实

  - **连接与通道：14 条**，1 条严重——按主机名连接时 NIO 会对多个地址各试一次（Happy Eyeballs），每次都装了一套共享状态的
    握手守卫，落败的那次（`localhost` 的 `::1` 被拒、IPv6 不通或更慢）会把整次连接判成失败；现有测试全用 `127.0.0.1` 所以没撞上。
    其余：跳板机在外层链路僵死时握手时限和取消都放不开；几处等待不响应取消；远程转发的登记表按（主机，端口）做键会互相覆盖；
    主动关闭被报成网络错误；Debug 构建下泄漏未完成的 promise 会崩；实际缓冲约为窗口的 2 倍（最大包长允许到 16 MiB 时可达 2 GiB）；
    换钥时重新回调主机密钥校验、没钉住首次的密钥；认证完成后口令和私钥还留在内存里。
  - **SFTP：14 条**——关闭后在途的请求可能打到复用了句柄编号的另一个文件（OpenSSH 会复用）；`readAll` 可能把截断的数据当成功；
    取消中的 OPEN 可能在服务器上留下句柄；非 UTF-8 文件名有损解码（改成能原样保留字节的 `SFTPPath`）；
    测试服务端的路径限制能被符号链接绕过；以及零长度读、编号回绕、溢出等边界。
  - **算法与扩展接口补丁：没有严重 / 高 / 中的问题**，8 条低危：主机密钥算法不能按连接限制（注册即全进程生效）、
    一次握手里两次读注册表没取快照、自定义密钥交换没拒绝取值为 1 的对端值、注册可以占用证书类型名、
    NIOSSH 从不主动换钥（CTR + HMAC 下包序号会在同一把密钥里回绕）等。

    这个结论来自 subagent 的复现，真实 sshd 上的验证排给了 E 线（换钥期间上传大文件）。

## 5. 风险与已定的取舍

- **一次切换，不并存**：同一个构建图里只能有一个 NIOSSH 模块，Citadel 在 Apple 版上编不过，所以开发分支上 Citadel 与
  USSHKit 先停编（`Package.swift` 里标着 `SSH-STACK-WIP`），接好之后恢复。中间状态不能发布。
- **DH 的大数运算**用 attaswift/BigInt（已有依赖），不是恒定时间。指数每次连接只用一次，实际风险低，和 Citadel 今天的做法相同；
  RSA 改用 swift-crypto 的 `_CryptoExtras`（BoringSSL），比 Citadel 手写的 BigInt RSA 更稳妥。
- **不照抄 Citadel**：新代码按 RFC 4251–4254、RFC 8332、SFTP v3 草案写，Citadel 只用来对照行为。`bcrypt_pbkdf` 的 C 实现
  是 OpenBSD 的（BSD 许可），保留，只改 target 名。
- **uAppKit 按 tag 被消费**：uTerm 的迁移要等 uAppKit 发新版，开发期间用本地路径引用验证。升级算协议层变更，发版说明里要写。
- **补丁 0005**（Wellz 基线上消两条 Sendable 警告）已丢弃（2026-11-24，维护者定）：换到 Apple 基线后不再需要，
  重写落地前 main 上那两条警告照旧。

## 6. 维护者 2026-11-25 定的五件事（按最佳实践做，尽量不让用户困惑）

1. **已信任的主机突然要退到 SHA-1**：一直只会 SHA-1 的老设备照旧静默降级；以前用现代算法连上过（主机密钥已在信任记录里）、
   这次却要退到旧算法的，先问用户。USSHKit 给 App 一个降级前的决定钩子（K 线），App 侧判断「是不是以前连过」并弹确认（T 线 uTerm、U 线 uTable）。
   不能问用户的连接（预览、命令行、保持会话收尾）直接以类型化错误失败、归为不可重试。不新增 `@Model` 字段（免得要部署 CloudKit schema），
   「这台确认过可以用旧算法」记在本机。
2. **测试服务端不进 Release**：`USSHTestServer` 只在 debug 配置编译，Release 下是空模块（K 线，实测前后大小）。
3. **`utablectl` 加按指纹信任**：照 uTerm 的 `utermctl trust`，必须给出与这次实际看到的完全一致的指纹，不提供「接受任何密钥」（U3 线）。
4. **uTable 界面探针线程泄漏**：单独一条线在 uTable main 的新 worktree 上核实、查根因、修（L 线，分支 `fix/probe-thread-leak`）。
5. **发版**：以上合并、两个 App 全量与审查都过之后：uAppKit 合 main 打 tag → 两个 App 改回按版本引用、去掉 DO-NOT-MERGE 提交、重新解析依赖 → 全量复跑。
   两个 App 现在都是 `upToNextMinorVersion` 从 `1.25.0`，所以必须同时改 pbxproj 的版本要求。tag 推上去就改不了，推之前再核一遍。

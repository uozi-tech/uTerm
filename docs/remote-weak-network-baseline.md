### 读数的边界

- 同一档各轮之间可能差很多（2026-11-08 高丢包 5% 直连一次 7.6 Mbps / 16 fps、一次 1.7 Mbps / 1.7 fps），看中位数也要看范围。
- 抖动按包独立取值，UDP 上会大量乱序，比真实网络（多为排队造成的、基本有序的抖动）更狠。
- 中继 TCP 是把手机到 Mac 整段当一跳模拟：丢包表现为该段数据晚到 200 ms（重传），没有真实 TCP 的拥塞窗口收缩。
- 建连那组的打洞在本机回环上进行，差网络只加在手机到中继这一段。
- 合成画面是 4:2:0 色块加点阵字，编码器对它的压缩率和真实桌面不同；局部变化几档的码率要和真机读数对照着看。
- 模拟测不到的：真实 TCP 拥塞控制、蜂窝空口调度、Wi-Fi 与蜂窝切换时系统的真实时序——这些要用 Network Link Conditioner 在真机上补。
